# Early Delay v0.1.0-alpha - offline measurements

All numbers below come from `python3 tools/offline.py measure docs/MEASUREMENTS.md`, which compiles
`tests/offline/offline.cpp` against the **same engine header the plugin uses**
(`plugin/src/early_delay_dsp.h`) and runs it at 44.1 kHz in 128-frame blocks, in place, like the MPC.
Nothing here was measured on an MPC; see "Not verified" at the end.

## Summary

| Requirement | Result |
|---|---|
| Delay range 1.75-900 ms | first echo within 0.1 ms of the setting across the range (converter latency is compensated) |
| Variable clock: pitch moves with time | Time 300 -> 600 ms on a steady 1 kHz tone: the output drops to ~500 Hz until the old memory has played out, then returns to 1 kHz. HOLD + Time 300 -> 600 ms: the frozen loop drops exactly one octave (1000 -> 500 Hz) |
| ~8 kHz wet bandwidth at short times, darker/aliased at long times | -3 dB at 8.1-8.4 kHz up to the clock knee (Bandwidth 60 %), 6.3 kHz at 300 ms, 4.5 kHz at 500 ms, 2.7 kHz at 900 ms. At low Bandwidth/long times the clock falls below 2x the signal and the 3 kHz test tone comes back mostly as aliases |
| ~12-bit grit, companding with imperfect tracking (breathing) | Grit 35 % = 11.9 bits; THD+N 2-3 % at -12 dBFS; the noise floor follows the signal (breathing) |
| Stable loop gain | at +/-99 % feedback every repeat is quieter than the last (about -1 dB per repeat with Grit 35 %); abuse test (+12 dBFS noise, everything at max) stays bounded and finite |
| Inverted feedback | every repeat flips polarity (correlation of repeat 2 vs 1 = -0.49 vs +0.50 for positive feedback) |
| HOLD | level flat within 0.1 dB over 60 s; input fully isolated (bit-identical output with or without input); loop repeats exactly (correlation 1.00000) |
| Stereoize, mono-compatible | L/R correlation drops from 1.0 to 0.49-0.77; mono sum loses 0.5-1.3 dB broadband and never more than 3.4 dB in any octave (no cancellation notches); bass below 150 Hz stays near-mono (correlation 0.90-0.99) |
| Real-time cost | about 1.2 % of one x86-64 core per stereo instance, flat across block sizes 32-512 |

### How to read the figures

- **Wet bandwidth.** "Bandwidth" (0-100 %) sets both the converter filter frequency (4.5 kHz at 0 %, 8 kHz at
  60 %, 11.9 kHz at 100 %) and the number of memory cells (2 048 / ~10 800 / 32 768). Up to the knee
  (cells / 44.1 kHz: 46 ms, 245 ms, 743 ms) the clock runs at 44.1 kHz and the filters set the bandwidth. Above
  the knee the clock is cells / time, the filters follow it to 0.42 x clock, and the 4-pole skirts let
  aliasing and images through on purpose.
- **Impulse response.** A lone click arrives while the compressor is at its silence gain (+34 dB), so it hits the
  ADC clip and the expander then scales it back: the echo of a click is short and about 20 dB lower than the click.
  This is how companded delays treat transients; on music the onsets are softened rather than lost.
- **THD+N at Grit 0** is about 2 % at -12 dBFS. It comes from the op-amp stages (deliberately asymmetric) and the
  compander. The plugin is never clean on purpose.
- **Idle noise** is the output-stage hiss (about -99 dBFS at Grit 0, -89 at 35 %, -82 at 100 %). The ADC noise
  (12 bits) is pushed down by the expander when the input is silent and comes back up with the signal.
- **Feedback.** The loss per repeat depends on the material and Grit: Grit adds expander lag, which can only lose
  level, never add it. In the burst test the loss per repeat at +/-99 % is about 0.6 dB (Grit 0), 1.0 dB (35 %),
  1.7 dB (100 %). Infinite sustain is HOLD's job.

## Not verified (needs the MPC Live III)

- **CPU on the device.** The figures above are from an x86-64 build server. The Cortex-A55 in the Live III does
  much less work per clock. Rough estimate: 4-8 % of one core per instance. Not measured; check it with the
  MPC's CPU meter on several instances.
- **Host behaviour.** Covered only by the SDK's host simulator (load sequence, parameter-0 nudge, in-place buffers,
  block sizes 32/128/512, state round-trip, NaN/denormal checks). These were not tested on the MPC: the real
  touchscreen skin, Q-Link assignments, preset list, project save/load and automation.
- **Sound vs. the original hardware.** No recordings of the original unit were available. Every figure above is
  measured on this model only.
- **arm32/arm64 binaries** were built and checked by the SDK validator (ELF format, symbol versions, exports), but
  they were not run here; only the native build ran.
